3.5 Ampliación

Significado del "_" : 

👉 Aquí this._nombre es una convención: el guion bajo (_) sugiere que no deberías acceder directamente desde fuera, aunque técnicamente sí puedes hacerlo.

🚫 Pero no es realmente privada

En versiones antiguas de JavaScript (antes de ES2020), no existía una forma real de hacer propiedades privadas, así que se usaba el guion bajo como advertencia visual.

Es decir:

"No accedas directamente a esto, es solo para uso interno de la clase."

✅ Forma moderna (propiedades privadas reales)

Desde ES2020, ya existe una sintaxis oficial para propiedades privadas reales: usando el #.

Aquí #nombre sí es realmente privado: no puedes acceder a él desde fuera de la clase.

---------------

JavaScript no tiene modificadores de acceso tradicionales como public, protected o private (al menos, no como en Java).
Sin embargo, sí existen mecanismos y convenciones que logran un efecto similar.

1. 🟢 public → por defecto todo es público

En JS, todas las propiedades y métodos son públicos a menos que se indique lo contrario

2. 🟡 protected → no existe formalmente, pero se simula con convención

No hay protected en JavaScript.
Lo más cercano es usar un guion bajo _ como señal de “no lo uses fuera de la clase o sus herederos”.

🔸 En resumen: _nombre no está realmente protegido, pero los desarrolladores entienden que no deberían tocarlo directamente.

3. 🔴 private → desde ES2020 se usa #

JavaScript introdujo campos privados reales con el prefijo #.
