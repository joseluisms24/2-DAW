2.2 Arquitectura de ejecución

Cada navegador web tiene su propia forma de interpretar la interacción con un usuario. El resultado de esta interacción, en cualquier caso, se inicia con el usuario indicando la dirección del recurso al que quiere acceder y termina por la visualización del recurso por parte del navegador en la pantalla del usuario.  La forma de realizar este proceso depende  del propósito del navegador  y de la configuración del mismo. De esta forma, un navegador puede estar más centrado en ofrecer una respuesta más rápida, en mostrar una respuesta más fiel al contenido del recurso obtenido, en priorizar los aspectos de seguridad de las comunicaciones con el servidor etc. 

Para poder llevar a cabo el proceso descrito anteriormente, cada navegador está formado por una serie de elementos y componentes determinados que conforman lo que se denomina arquitectura del navegador. A pesar de que cada navegador tiene su propia arquitectura, la gran mayoría de ellos coinciden en unos componentes básicos en todos ellos, a lo cual llamamos arquitectura de referencia.  Podemos destacar los siguientes: 

🧩 1. Subsistema de interfaz de usuario

  • Es la parte visible del navegador: barra de direcciones, botones, pestañas, menús, etc.

  • Permite la interacción del usuario con el navegador.

  • No se involucra directamente en el procesamiento del contenido web.

🚀 2. Subsistema del motor del buscador o motor de navegación

  • Es el corazón del navegador.

  • Se encarga de coordinar los procesos para cargar, interpretar y mostrar el contenido web.

  • Ejemplos:

    • Blink (usado en Chrome y Edge)

    • Gecko (Firefox)

    • WebKit (Safari)

🎨 3. Subsistema de renderizado

  • Convierte el código HTML, CSS y JS en contenido visual en pantalla.

  • Construye el DOM (Document Object Model) y el árbol de renderizado para pintar los elementos.

  • Se encarga del layout (posicionamiento) y del repintado (visualización).

🌐 4. Subsistema de comunicaciones

  • Gestiona las conexiones de red: HTTP/HTTPS, WebSocket, etc.

  • Se encarga de descargar archivos como HTML, CSS, JS, imágenes desde el servidor web.

  • Usa protocolos y sockets para establecer la comunicación.

📜 5. Intérprete de JavaScript

  • Ejecuta el código JavaScript de las páginas web.

  • Es responsable de la lógica, interactividad y manipulación del DOM.

  • Motores JS populares:

    • V8 (Chrome, Edge)

    • SpiderMonkey (Firefox)

    • JavaScriptCore (Safari)

📂 6. Parser XML

  • Analiza y transforma archivos XML en estructuras DOM.

  • Es importante para tecnologías como AJAX, SVG, RSS, etc.

  • También puede intervenir en el análisis de HTML bien formado.

🖼️ 7. Componente de visualización

  • Recibe la salida del motor de renderizado y la pinta en pantalla.

  • Controla el viewport, los gráficos, fuentes, imágenes y animaciones.

  • Gestiona el repaint y reflow cuando hay cambios visuales.

💾 8. Subsistema de persistencia de datos

  • Administra el almacenamiento local en el navegador:

    • Cookies

    • LocalStorage / SessionStorage

    • IndexedDB

    • Caché del navegador

  • Es clave para funcionalidades como sesiones de usuario, almacenamiento offline, datos de formularios, etc.

PARA SABER MÁS

¿Qué es el sandboxing?. Es una técnica de seguridad informática que se utiliza para aislar programas o procesos en un entorno controlado, conocido como sandbox (caja de arena). Dentro de este entorno, las aplicaciones o procesos ejecutan sus operaciones con permisos limitados y acceso restringido a los recursos del sistema. El objetivo principal del sandboxing es proteger el sistema operativo y otros programas de posibles comportamientos maliciosos, errores o vulnerabilidades que el software podría contener.

Ejemplos de tecnologías de sandboxing:

  • Docker: Utiliza contenedores para aislar aplicaciones y gestionar su ejecución de manera independiente.

  • VirtualBox / VMware: Emplean máquinas virtuales para aislar sistemas operativos completos.

  • Firejail: Una herramienta de sandboxing en Linux que restringe el entorno de ejecución de aplicaciones.

  • Google Chrome: Usa un modelo de seguridad de sandbox para aislar las pestañas de navegación web.
